Cuando empecé Piclink tenía dos repos separados: uno para la web y otro para la app.
Cada cambio de lógica lo copiaba a mano entre los dos. Duró poco: a la tercera vez
que un bug se arregló en un lado pero no en el otro, junté todo en un monorepo.

## La idea que lo ordena todo

La regla es simple: lo que es lógica de negocio vive en un paquete compartido; lo que
es interfaz vive en cada app. La web la sirvo con Astro, la app con React Native, y en
medio hay un `packages/core` que las dos importan.

```txt title="estructura"
apps/
  web/      # Astro
  mobile/   # React Native
packages/
  core/     # tipos, validaciones, lógica de negocio
  ui/       # componentes que sí se comparten
```

## Lo que aprendí a las malas

No todo se comparte. Intenté compartir componentes de UI entre web y móvil y terminé
con un monstruo lleno de `if (Platform)`. Hoy comparto tipos y lógica sin pena, pero
la interfaz la escribo dos veces. Suena a más trabajo; en la práctica es menos, porque
cada app queda limpia.

<Nota>
Empieza compartiendo solo tipos. Cuando duela copiar una función, súbela a `core`. No
antes: compartir demasiado pronto es peor que no compartir.
</Nota>
